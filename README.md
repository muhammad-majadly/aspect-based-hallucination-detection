# Aspect-Based Hallucination Detection

Code and benchmark dataset for **"Hallucination Detection and Correction in
Aspect-Based Summarization of Scientific Papers."**

Given a scientific paper and an aspect-based summary sentence generated for
it (Motivation, Contribution, Methodology, Main Results, or Paper Goal), the
task is to decide whether that sentence is a *hallucination* -- a claim not
actually supported by the source paper. This repo contains:

- **A 50-paper, 900-sentence benchmark** of aspect-based summary sentences,
  all generated by a single small open model (Qwen2.5-0.5B-Instruct), with
  every sentence hand-labeled for hallucination status (and, when
  hallucinated, whether it is intrinsic or extrinsic).
- **Code to run and evaluate seven hallucination detectors** on a 25-paper
  held-out subset of that benchmark: two proprietary LLM judges
  (GPT-4-turbo, GPT-4o), two small open instruction-tuned LLMs used
  zero-shot (Gemma-2-2b-it, Llama-3.2-1B), two dedicated fact-checking tools
  (SummaC, MiniCheck), and our own lightweight detector ("Our Model":
  sentence-similarity retrieval + NLI + a learned aggregator).

## Repository layout

```
data/
  dataset.csv        # 900 rows: Sentence, Paper Name, Aspect, Hallucination, ...
  papers/            # 50 source-paper JSONs (id.json), referenced by dataset.csv via manifest.py
models/
  aggregator.joblib       # frozen "Our Model" aggregator (see "Our Model" below)
  aggregator_meta.json    # its C / decision threshold / training-set size
code/
  config.py, manifest.py, dataset_utils.py, evidence.py   # shared utilities
  openai_client.py, nli_backend.py, feature_extraction.py # model backends
  run_gpt4.py, run_gemma.py, run_llama.py                 # LLM-judge baselines
  run_summac.py, run_minicheck.py                         # fact-checking-tool baselines
  run_our_model.py                                         # our detector
  evaluate.py                                              # accuracy / precision / recall / F1
results/
  predictions_<model>.csv   # the actual predictions behind the numbers below
```

## Installation

Requires Python 3.9+.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

`run_gemma.py` and `run_llama.py` use [MLX](https://github.com/ml-explore/mlx)
and only run on Apple Silicon Macs. Every other script is platform-independent.

**SummaC needs a separate environment** (its pinned dependencies conflict
with the rest): see `requirements-summac.txt`.

```bash
python3 -m venv .venv-summac
.venv-summac/bin/pip install -r requirements-summac.txt
```

## API key setup (GPT-4-turbo / GPT-4o only)

`run_gpt4.py` needs an OpenAI API key. Either:

```bash
export OPENAI_API_KEY=sk-...
```

or create `code/api_key.txt` containing just the key (already covered by
`.gitignore` -- never commit this file).

No other script needs an API key or any credentials.

## Dataset format

`data/dataset.csv` has one row per (paper, aspect, summary sentence):

| Column | Meaning |
|---|---|
| `Sentence` | The generated summary sentence being judged. |
| `Paper Name` | Matches a title resolved by `code/manifest.py` to a JSON file in `data/papers/`. |
| `Aspect` | One of `Motivation`, `Contribution`, `Methodology`, `Main Results`, `Paper Goal`. |
| `Intrinsic Hallucination` / `Extrinsic Hallucination` | `Yes`/`No`, mutually exclusive when `Hallucination` is 1. |
| `Hallucination` | Gold label: `1` (hallucinated) or `0` (not). |

**50 papers, 900 sentences, 131 hallucinated (14.6%)**: 27 NLP papers (448
sentences, 45 hallucinated) and 23 CV papers (452 sentences, 86 hallucinated).
Every hallucination is naturally-occurring (the model's own output), not a
synthetic perturbation.

Each JSON in `data/papers/` has the shape `{"paper_title": ..., "sections":
[{"section": "Introduction", "chunks": ["...", "..."]}, ...]}`.

### Held-out test set

All seven detectors are evaluated on a fixed **25-paper subset** (478
sentences, 80 hallucinated, 16.7%) -- see `config.TEST_PAPERS`. Every
`run_*.py` script defaults to this subset; pass `--all-papers` to run against
the full 50-paper dataset instead (only meaningful for `run_our_model.py
--retrain`, see below).

## Running each model

```bash
cd code

# LLM judges (need OPENAI_API_KEY / api_key.txt):
python run_gpt4.py                       # both gpt-4-turbo and gpt-4o
python run_gpt4.py --models gpt-4o        # just one

# Small open LLMs, zero-shot (Apple Silicon / MLX):
python run_gemma.py
python run_llama.py

# Dedicated fact-checking tools:
python run_minicheck.py                          # main .venv
../.venv-summac/bin/python3 run_summac.py        # isolated venv, see above

# Our detector (frozen aggregator, reproduces the numbers below):
python run_our_model.py
```

Each script writes `results/predictions_<model>.csv` (or reuses/extends it
if partially done -- every script is resumable).

## "Our Model": frozen vs. retrained aggregator

"Our Model" is a logistic-regression aggregator over 13 similarity/NLI/lexical
features (see `code/feature_extraction.py`), replacing a hand-tuned decision
rule. `run_our_model.py` has two modes:

- **Default** (`python run_our_model.py`): loads the frozen aggregator in
  `models/aggregator.joblib`. Its weights, regularization strength, and
  decision threshold were selected via leave-one-paper-out cross-validation
  on an internal 17-paper training split from an earlier iteration of this
  project, disjoint from the released benchmark -- that split isn't
  released, so this frozen model is what makes the reported numbers
  reproducible without it. This is the model reported in the paper.
- **`--retrain`**: refits the aggregator from scratch, entirely
  self-contained within this benchmark -- training on the 25 *non-test*
  papers of the 50-paper dataset (identical leave-one-paper-out C/threshold
  selection), then evaluating on the same 25-paper held-out test set. This
  is a purely local computation (no API cost) and is the path we recommend
  going forward, since that training data shares the same generator and
  paper distribution as the test set and may generalize better than the
  frozen model above.

## Optional aspect-to-section evidence mapping

`code/evidence.py` implements a fixed aspect -> section mapping (e.g.
Methodology -> everything after Related Work). It is **disabled by default**
(`config.USE_ASPECT_MAPPING = False`): the final experiments retrieve
evidence from the *full* paper text for GPT-4-turbo, GPT-4o, Gemma-2-2b-it,
Llama-3.2-1B, and "Our Model"'s retrieval step. `run_summac.py` and
`run_minicheck.py` are a deliberate, documented exception -- they call
`evidence.get_evidence()` directly regardless of this flag, because their
NLI/fact-checking backends are intractably slow against a full paper; see
the docstrings in those two scripts.

## Running the full evaluation

After running every `run_*.py` script above (or using the `results/*.csv`
files already committed in this repo, which are exactly what produced the
numbers below):

```bash
cd code
python evaluate.py
```

This computes accuracy/precision/recall/F1 for every `results/predictions_*.csv`
file, overall and broken down by aspect, and writes `results/comparison_report.md`.

## Results

Held-out test set: 478 sentences, 80 hallucinated (16.7%), 25 papers.

| Model | N | Accuracy | Precision | Recall | F1 |
|---|---|---|---|---|---|
| GPT-4o | 478 | 0.818 | 0.476 | 0.863 | **0.613** |
| Our Model | 478 | 0.799 | 0.523 | 0.550 | 0.536 |
| GPT-4-turbo | 478 | 0.745 | 0.336 | 0.537 | 0.413 |
| MiniCheck | 478 | 0.812 | 0.422 | 0.338 | 0.375 |
| Gemma-2-2b-it | 473 | 0.524 | 0.201 | 0.620 | 0.303 |
| SummaC-ZS | 478 | 0.730 | 0.212 | 0.225 | 0.218 |
| Llama-3.2-1B | 478 | 0.462 | 0.133 | 0.400 | 0.199 |

GPT-4o has the strongest overall F1; **Our Model has the second-highest F1**,
ahead of GPT-4-turbo and every other baseline, while using retrieval and NLI
backbones (`sentence-transformers/all-mpnet-base-v2`,
`microsoft/deberta-large-mnli`) that together total on the order of half a
billion parameters plus a 13-parameter learned aggregator -- several orders
of magnitude fewer than GPT-4-class models. Per-aspect breakdowns for all
seven models are in `results/comparison_report.md` (regenerate with
`python evaluate.py`) and in the paper's Experiments section.

These are the only seven models evaluated in the main comparison. An earlier
hand-tuned decision rule (the predecessor to the learned aggregator above)
is discussed only in the paper's ablation study and is not part of this
repo's main evaluation.
