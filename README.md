# Aspect-Based Hallucination Detection

Code and benchmark dataset for **"Hallucination Detection and Correction in
Aspect-Based Summarization of Scientific Papers."**

Given a scientific paper and an aspect-based summary sentence generated for
it (Motivation, Contribution, Methodology, Main Results, or Paper Goal), the
task is to decide whether that sentence is a *hallucination* -- a claim not
actually supported by the source paper. This repo contains:

- **A 50-paper, 1,721-sentence benchmark** of aspect-based summary sentences,
  all generated by a single small open model (Qwen2.5-0.5B-Instruct) under
  two decoding settings (greedy and temperature=0.8 sampling), with every
  sentence hand-labeled for hallucination status (and, when hallucinated,
  whether it is intrinsic or extrinsic).
- **Code to run and evaluate seven hallucination detectors** on a 25-paper
  held-out subset of that benchmark: two proprietary LLM judges
  (GPT-4-turbo, GPT-4o), two small open instruction-tuned LLMs used
  zero-shot (Gemma-2-2b-it, Llama-3.2-1B), two dedicated fact-checking tools
  (SummaC, MiniCheck), and our own lightweight detector ("Our Model":
  sentence-similarity retrieval + NLI + a learned aggregator).

## Repository layout

```
data/
  dataset.csv        # 1,721 rows: Sentence, Paper Name, Aspect, Hallucination, Temperature, ...
  papers/            # 50 source-paper JSONs (id.json), referenced by dataset.csv via manifest.py
  synthetic/          # 10 fabricated papers + 150 sentences used to augment aggregator training (see below)
models/
  aggregator.joblib       # frozen "Our Model" aggregator (see "Our Model" below)
  aggregator_meta.json    # its C / decision threshold / training-set composition
code/
  config.py, manifest.py, dataset_utils.py, evidence.py   # shared utilities
  openai_client.py, nli_backend.py, feature_extraction.py # model backends
  generate_synthetic_data.py                               # (re)generates data/synthetic/
  run_gpt4.py, run_gemma.py, run_llama.py                 # LLM-judge baselines
  run_summac.py, run_minicheck.py                         # fact-checking-tool baselines
  run_our_model.py                                         # our detector
  evaluate.py                                              # accuracy / precision / recall / F1
results/
  (created by the scripts below; not committed -- run them to regenerate predictions_<model>.csv and comparison_report.md)
```

## Installation

Requires Python 3.9+.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

`run_gemma.py` and `run_llama.py` use [MLX](https://github.com/ml-explore/mlx)
and only run on Apple Silicon Macs. Every other script is platform-independent.

**SummaC needs a separate environment** (its pinned dependencies conflict
with the rest): see `requirements-summac.txt`.

```bash
python3 -m venv .venv-summac
.venv-summac/bin/pip install -r requirements-summac.txt
```

## Dataset format

`data/dataset.csv` has one row per (paper, aspect, summary sentence, decoding
setting):

| Column | Meaning |
|---|---|
| `Sentence` | The generated summary sentence being judged. |
| `Paper Name` | Matches a title resolved by `code/manifest.py` to a JSON file in `data/papers/`. |
| `Aspect` | One of `Motivation`, `Contribution`, `Methodology`, `Main Results`, `Paper Goal`. |
| `Intrinsic Hallucination` / `Extrinsic Hallucination` | `Yes`/`No`, mutually exclusive when `Hallucination` is 1. |
| `Hallucination` | Gold label: `1` (hallucinated) or `0` (not). |
| `Temperature` | `0` (greedy decoding) or `0.8` (sampled decoding) -- which generation this sentence came from. |

**50 papers, two generations each, 1,721 sentences total, 400 hallucinated
(23.3%)**: 900 sentences from greedy decoding (131 hallucinated, 14.6%) and
821 from temperature=0.8 sampling (269 hallucinated, 32.8%) over the
identical 50 papers. Every hallucination is naturally-occurring (the model's
own output), not a synthetic perturbation. All scripts select one decoding
setting at a time via `--temperature {0,0.8}` (default `0`); see
`dataset_utils.load_dataset_rows`.

Each JSON in `data/papers/` has the shape `{"paper_title": ..., "sections":
[{"section": "Introduction", "chunks": ["...", "..."]}, ...]}`.

### Held-out test set

All seven detectors are evaluated on a fixed **25-paper subset**, in each
decoding setting -- see `config.TEST_PAPERS` (`--temperature 0`) and
`config.TEST_PAPERS_TEMP08` (`--temperature 0.8`), selected automatically via
`config.test_papers_for(temperature)`. Every `run_*.py` script defaults to
this subset; pass `--all-papers` to run against the full 50-paper dataset
instead (only meaningful for `run_our_model.py --retrain`, see below).

## Running each model

```bash
cd code

# LLM judges (need OPENAI_API_KEY / api_key.txt):
python run_gpt4.py                       # both gpt-4-turbo and gpt-4o, temperature=0
python run_gpt4.py --models gpt-4o --temperature 0.8   # just one, temperature=0.8

# Small open LLMs, zero-shot (Apple Silicon / MLX):
python run_gemma.py
python run_llama.py

# Dedicated fact-checking tools:
python run_minicheck.py                          # main .venv
../.venv-summac/bin/python3 run_summac.py        # isolated venv, see above

# Our detector (frozen aggregator, reproduces the numbers below):
python run_our_model.py
```

Every script accepts `--temperature {0,0.8}` (default `0`) to select which
decoding setting's rows to evaluate; the reported results (below) combine
both settings by running each script twice and pooling the two output files.
Each script writes `results/predictions_<model>.csv` (or reuses/extends it
if partially done -- every script is resumable), so rename the output file
between the two `--temperature` runs before combining them.

## "Our Model": frozen aggregator, synthetic augmentation, and retraining

"Our Model" is a logistic-regression aggregator over similarity/NLI/lexical
features (see `code/feature_extraction.py`), replacing a hand-tuned decision
rule. `run_our_model.py` has two modes, which use different feature sets:

- **Default** (`python run_our_model.py`): loads the frozen aggregator in
  `models/aggregator.joblib` -- 13 features, retrieval over the top-5
  evidence candidates. This is the model reported in the paper's main
  results, trained on the union of two sources (see
  `models/aggregator_meta.json`): (1) an internal 17-paper split from an
  earlier iteration of this project, disjoint from the released benchmark
  and **not released here**, and (2) 150 synthetic sentences
  (`data/synthetic/`, generated by `code/generate_synthetic_data.py`), which
  **are** released. Its regularization strength and decision threshold were
  selected via leave-one-paper-out cross-validation over the combined
  training set.
- **`--retrain`**: refits the aggregator from scratch, entirely
  self-contained within this benchmark -- 19 features (`feature_extraction.
  FEATURES_13_PLUS_4_PLUS_FP`, adding acronym-mismatch, numeric-overlap,
  self-reference, question, hedge-opinion, and meta-commentary checks to the
  original 13), retrieval over the top-6 evidence candidates, training on
  the 25 *non-test* papers of the selected `--temperature` (identical
  leave-one-paper-out C/threshold selection), then evaluating on the same
  25-paper held-out test set. Add `--include-synthetic` to also add the 150
  synthetic sentences to this training set (still fully self-contained,
  since both sources are released). The validated-best configuration is
  `--retrain --include-synthetic --temperature 0.8`. Both modes are purely
  local computations (no API cost).

### Why synthetic augmentation, and why 150 sentences (not more)

The 150 synthetic sentences are 10 fabricated (not real) scientific
passages, each paired with 5 sentences entailed by the passage, 5 that
directly contradict a specific fact in it, and 5 neutral (topically related
but neither confirmed nor denied) -- all with known ground truth by
construction. Adding them to the 17-paper training split improved held-out
F1 from 0.478 to 0.519, apparently by giving the logistic regression cleaner,
less ambiguous examples of each relationship than the noisier real training
data alone provides.

We tried a second batch of 150 more synthetic sentences (300 total) and it
made things *worse* (F1 dropped to 0.483) -- more synthetic data is not
uniformly better here, so we kept only the first, better-performing batch of
150 rather than tuning this choice further against the held-out test set.
We also confirmed the synthetic sentences alone (no real training data)
reach only F1=0.447, and the real 17-paper split alone reaches F1=0.478 --
the two sources are complementary; neither alone matches their combination.

## Optional aspect-to-section evidence mapping

`code/evidence.py` implements a fixed aspect -> section mapping (e.g.
Methodology -> everything after Related Work). It is **disabled by default**
(`config.USE_ASPECT_MAPPING = False`): the final experiments retrieve
evidence from the *full* paper text for GPT-4-turbo, GPT-4o, Gemma-2-2b-it,
Llama-3.2-1B, and "Our Model"'s retrieval step. `run_summac.py` and
`run_minicheck.py` are a deliberate, documented exception -- they call
`evidence.get_evidence()` directly regardless of this flag, because their
NLI/fact-checking backends are intractably slow against a full paper; see
the docstrings in those two scripts.

## Running the full evaluation

After running every `run_*.py` script above:

```bash
cd code
python evaluate.py
```

This computes accuracy/precision/recall/F1 for every `results/predictions_*.csv`
file, overall and broken down by aspect, and writes `results/comparison_report.md`.

## Results

Held-out test set, combined across both decoding settings: 873 sentences,
187 hallucinated (21.4%), 25 papers in each setting.

| Model | N | Accuracy | Precision | Recall | F1 |
|---|---|---|---|---|---|
| GPT-4o | 873 | 0.780 | 0.492 | 0.845 | **0.622** |
| Our Model (retrained, self-contained) | 873 | 0.790 | 0.508 | 0.701 | 0.589 |
| GPT-4-turbo | 873 | 0.742 | 0.445 | 0.818 | 0.576 |
| MiniCheck | 873 | **0.804** | 0.540 | 0.572 | 0.556 |
| Our Model (frozen, shipped) | 873 | 0.759 | 0.450 | 0.556 | 0.498 |
| SummaC-ZS | 873 | 0.734 | 0.397 | 0.465 | 0.429 |
| Llama-3.2-1B | 873 | 0.494 | 0.206 | 0.476 | 0.287 |
| Gemma-2-2b-it | 858 | 0.566 | 0.221 | 0.400 | 0.285 |

GPT-4o has the strongest overall F1; **Our Model's self-contained retrain
has the second-highest F1**, ahead of GPT-4-turbo and every other baseline,
and the second-highest accuracy (behind only MiniCheck), while using
retrieval and NLI backbones (`sentence-transformers/all-mpnet-base-v2`,
`microsoft/deberta-large-mnli`) that together total on the order of half a
billion parameters plus a 19-parameter learned aggregator -- several orders
of magnitude fewer than GPT-4-class models. Per-aspect breakdowns for all
seven models are in `results/comparison_report.md` (regenerate with `python
evaluate.py`) and in the paper's Experiments section.

These are the only seven models evaluated in the main comparison. An earlier
hand-tuned decision rule (the predecessor to the learned aggregator above)
is discussed only in the paper's ablation study and is not part of this
repo's main evaluation.

## Reproducing everything

```bash
python3 -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt
export OPENAI_API_KEY=sk-...
cd code
for t in 0 0.8; do
  python run_gpt4.py --temperature $t && python run_gemma.py --temperature $t \
    && python run_llama.py --temperature $t && python run_minicheck.py --temperature $t \
    && python run_our_model.py --temperature $t
  # rename each results/predictions_*.csv before the next iteration to avoid overwriting
done
cd .. && python3 -m venv .venv-summac && .venv-summac/bin/pip install -r requirements-summac.txt && .venv-summac/bin/python3 code/run_summac.py --temperature 0
cd code && python evaluate.py
```
